# Архитектурные решения «Города+»

ADDED: docs/decisions.md — обязательный журнал решений и новых путей.

## Сохранение структуры
Решение: сохранять существующие пути из cities_plus_bot.txt, устранять несовместимые контракты внутри файлов. Не удалять и не переименовывать файлы.
Причина: дерево согласовано пользователем; исходные слои содержали несовместимые импорты, DTO и поля ORM.
Альтернативы: удаление проекта и новая структура отклонены.

## Бесплатные API
Решение: базовый сценарий использует Open-Meteo, Nominatim и Wikipedia/Wikimedia без регистрации. Провайдеры с ключами необязательны. Не регистрировать сторонние аккаунты от имени пользователя.
Причина: отсутствие расходов и необходимости доступа к Google-почте.
Альтернативы: платные API не нужны для базового запуска. Наличие адаптера не означает, что реальный endpoint проверен.

## Конфигурация и секреты
Решение: app/config.py остаётся единственным источником настроек; вложенные представления временно поддерживают существующих потребителей плоских полей. Локальный .env не менять молча. Для тестов задавать отдельные настройки без реального токена.
Причина: в исходном шаблоне были реальные секреты; шаблон необходимо очистить, Telegram-токен — отозвать через BotFather.
Альтернативы: дублирование секретов в коде запрещено.

## HTTP
Решение: общая httpx.AsyncClient-сессия, явное закрытие при shutdown. Не смешивать методы aiohttp и httpx.
Причина: исходные точки входа использовали несовместимые типы HTTP-клиентов.
Альтернативы: полная миграция на aiohttp возможна позже, но не нужна для согласования текущего кода.

## База данных
Решение: PostgreSQL остаётся серверным вариантом; SQLite рассматривается как локальный вариант. Generic Uuid и JSON с PostgreSQL JSONB-вариантом обеспечивают переносимость. Изменения моделей требуют отдельной миграции перед обновлением существующей БД.
Причина: create_all создаёт новые таблицы, но НЕ обновляет существующие.
Альтернативы: не объявлять миграции и Docker рабочими до реальной проверки.

## Каскад и квоты
Решение: пропускать ненастроенные провайдеры до проверки квоты; затем проверять квоту и circuit breaker. Последний разрешённый запрос не должен терять результат из-за record_usage. OPEN хранится вместе с opened_at: cooldown переводит в HALF_OPEN, а не CLOSED.
Причина: истекающий ключ состояния терял информацию об открытом circuit breaker.
Альтернативы: проверять квоты для ненастроенных провайдеров не требуется. Исправлен ошибочный тест: теперь он отдельно проверяет ненастроенный, исчерпанный и доступный провайдеры; async Redis имитируется fakeredis, а не синхронным MagicMock.

## Роутеры и проверка
Решение: один root_router содержит упорядоченные подроутеры; check.py проверяет их вложенную регистрацию, а не требует 10 непосредственных детей Dispatcher.
Причина: aiogram запрещает прикреплять один Router сразу к двум родителям. Импорты пакетов bot и тип BaseProvider загружаются лениво, чтобы разорвать циклы.
Альтернативы: искусственное плоское включение уже прикреплённых роутеров отклонено.

## Статус проверки
Решение: считать блок проверенным только при явном выводе результатов, а не по пустому exit=0. Изолированный каталог .cache/site313 — временная среда проверки Python 3.13, НЕ подтверждение совместимости целевой Python 3.12.
Причина: наблюдались непоследовательные ошибки запуска Python (Access denied, запуск exe как текста, пустой вывод). Фактически выполненный предыдущий pytest: 5 passed, 4 failed; причины исправляются. Сквозная игра, миграции и Telegram polling ещё не подтверждены.

## Меню: постоянная reply-клавиатура с живыми кнопками
Решение: главное меню — reply-клавиатура (`app/keyboards/main_menu.py`) с `resize_keyboard=True`, `is_persistent=True` и `input_field_placeholder="Выберите раздел меню"`. Тексты кнопок вынесены в константы (`BTN_PLAY`, `BTN_GEO`, `BTN_PROFILE`, `BTN_ACHIEVEMENTS`, `BTN_LEADERBOARD`, `BTN_SETTINGS`, `BTN_HELP`) и в `MAIN_MENU_TEXTS`; все семь обрабатываются в `app/handlers/menu.py`, который подключается раньше игровых роутеров, поэтому нажатие «👤 Профиль» в разгар партии показывает профиль, а не трактуется как ход. Добавлена команда `/menu`. Исправлены места, где reply-клавиатура прикреплялась к `edit_text` (Telegram принимает там только inline-разметку): `menu.back_to_menu` и `cancel.cb_cancel` теперь снимают инлайн через `edit_reply_markup(reply_markup=None)` и отправляют меню отдельным сообщением. Оживлён «мёртвый» callback `"back"` из `app/keyboards/common.py` (кнопка «⬅️ Назад» ничего не делала) — его обрабатывает `menu.back_button`. Fallback отвечает меню с клавиатурой, чтобы её можно было вернуть любым сообщением. `ADDED: tests/unit/test_menu_keyboard.py` — новый путь: проверяет persistent-флаги, полноту и уникальность текстов кнопок, наличие хендлера на каждый текст и обработку `"back"`.
Причина: пользователь сообщил, что на мобильном меню «не выпадает». Разбор кода дал три причины: (1) у кнопок reply-клавиатуры не было хендлеров (кроме «🏆 Достижения», которой в клавиатуре не было), поэтому нажатия уходили в fallback; (2) не был выставлен `is_persistent`, и клиент мог сворачивать клавиатуру; (3) инлайн-кнопки «🏠 В меню»/«❌ Отмена» вызывали `edit_text(reply_markup=ReplyKeyboardMarkup)` — Bot API отвечает ошибкой, и меню не появлялось.
Альтернативы: оставить только inline-клавиатуры отклонено — на мобильном они привязаны к сообщению и уезжают вверх по истории; включать `is_persistent` без хендлеров отклонено — кнопки были бы видимыми, но нерабочими; дублировать экраны в меню отклонено — переиспользуются существующие хендлеры (`cmd_geo`, `cmd_profile`, `cmd_leaderboard`, `cmd_settings`, `cmd_help`, `show_achievements`).
Статус: исполнение в этой сессии невозможно (процессы запрещены). Проверено чтением: поля `is_persistent`/`input_field_placeholder` есть в aiogram 3.31.0 (`aiogram/types/reply_keyboard_markup.py`), импорт-чекер — 782 импорта без пропусков, тестов 219.

## Один экземпляр бота: файловый лок и ранняя диагностика конфликта
Решение: `app/utils/single_instance.py` — блокировка файла `data/bot.lock` средствами ОС (`msvcrt.locking` в Windows, `fcntl.flock` в POSIX), которая автоматически снимается при завершении процесса, поэтому «вечных» локов после падения не остаётся; лочится байт по смещению 1024, чтобы PID в начале файла оставался читаемым. `run.py` и `app/main.py` занимают лок при старте (отключается `BOT_SINGLE_INSTANCE=false`), при занятом локе сразу пишут понятную ошибку и выходят с кодом 1. Перед polling оба входа вызывают `app/bot/dispatcher.py::ensure_no_polling_conflict()`: короткий `get_updates(limit=1, timeout=0)` (обновления без `offset` не подтверждаются) заранее выявляет занятый токен и поднимает `PollingConflictError` из `app/exceptions.py`, который перехватывается в `__main__` и печатается без трейсбека. `ADDED: tests/unit/test_single_instance.py` — новый путь: захват/освобождение лока, повторный захват, идемпотентный `release()`, контекстный менеджер.
Причина: фактический запуск пользователя после починки сети дошёл до polling и выдал бесконечную серию `TelegramConflictError: terminated by other getUpdates request`. Диагностика через `Get-CimInstance Win32_Process` показала **шесть зависших процессов `run.py`** от прошлых сессий (созданы 01:57–02:34), которые одновременно забирали обновления. aiogram ловит `TelegramConflictError` в `_polling` общим `except Exception` и ретраит с backoff, поэтому бот не падал, а молча не работал. Лишние процессы были остановлены, а в код добавлена защита, чтобы это не повторялось.
Альтернативы: полагаться только на документацию («не запускайте дважды») отклонено — процессы остаются висеть после закрытия терминала; убивать чужие процессы автоматически отклонено — приложение не должно управлять системой; перейти на webhook отклонено — конфликт возникает и при активном webhook, и при втором поллере.
Статус: прогон в этой сессии невозможен; проверено чтением кода, запуском диагностических cmdlet'ов (список процессов, `docker ps`) и статическим чекером импортов (787 импортов, 0 пропусков). Тестов стало 222.

## Правило буквы «й» и лимит времени на ход
Решение: из «немых» окончаний исключена «й» — `SKIPPABLE_LAST_LETTERS` и `LETTERS_SKIP` теперь `{"ь", "ъ", "ы"}`, поэтому `last_letter("Волжский") == "й"`, и следующий город обязан начинаться на «й» («Йошкар-Ола»). Дублирующая реализация в `app/services/city_validator.py` больше не хранит свою логику, а делегирует в `app/utils/validators.last_letter`, чтобы правило было одно на весь проект. `scripts/healthcheck.py::_seed_cities()` получил город на «й» (Йошкар-Ола, 280 000) и замкнутую ветку Волжский(в…й) → Йошкар-Ола(й…а) → Астрахань(а…). Добавлен лимит времени на ход: настройка `MOVE_TIMEOUT` (по умолчанию 60 с, `0` — без ограничения), таймер взводится в `app/handlers/cities_game.py::_arm_timer()` после старта партии и каждого ответа бота; номер хода и дедлайн лежат в FSM (`turn`, `deadline`), запоздавшие таймеры игнорируются. По истечении времени фоновая задача завершает партию через `GameService.timeout()` со статусом `timeout`, очищает состояние и присылает сообщение; просрочка дополнительно проверяется при входящем ответе (`_expire_if_late`), поэтому правило работает и после перезапуска. В приглашении к ходу показывается `⏱ На ответ: N с.` (ключи `game.timer`/`game.timeout` в `app/utils/locales/{ru,en}.json`). Сдача и победа отменяют таймер.
Причина: пользователь сообщил, что бот работает, но нужны два правила — если город заканчивается на «й», следующий должен начинаться на «й» (раньше «й» молча отбрасывалась, и после «Волжского» требовалась «в»), и нужно ограничить время на ответ.
Альтернативы: отбрасывать «й» и дальше отклонено — противоречит правилу и ломает цепочку с «Йошкар-Олой»; отбрасывать все «немые» буквы включая «ы» оставлено — городов на «ы» в справочнике почти нет, и такое правило снова заводило бы игру в тупик; таймер только при входящем сообщении отклонён — тогда неответивший игрок держал бы партию вечно.
Статус: прогон в этой сессии невозможен (процессы запрещены). Проверено чтением, валидацией JSON-локалей (46 ключей, ключи добавлены) и статическим чекером импортов (792 импорта, 0 пропусков). Тестов 223, включая новый `test_timeout_finishes_game_with_timeout_status`.

## Города мира в справочнике
Решение: сид `data/seed/cities_seed.json` расширен с 25 российских городов до **112 записей из 70 стран** в русской транслитерации: 26 российских (добавлена Йошкар-Ола) и 86 зарубежных (Париж, Лондон, Берлин, Мадрид, Рим, Токио, Пекин, Сидней, Каир, Йоханнесбург, Цюрих, Щецин, Эдинбург, Яунде, Нью-Йорк, Сан-Паулу и др.). Покрыты редкие стартовые буквы «й», «ц», «щ», «э», «я» — боту заметно проще найти ответ на любую букву. Копия в `app/data/cities_seed.json` побайтно совпадает (зеркало). `scripts/load_cities.py` теперь по умолчанию **не фильтрует по странам** (`--countries ""` = все страны дампа), ограничение осталось опцией. `ADDED: tests/unit/test_cities_seed.py` — новый путь: проверяет плоскую структуру сида (защита от вложенных массивов), обязательные поля, уникальность после `normalize_city`, наличие мировых городов (≥50 стран), покрытие редких букв и побайтное совпадение зеркала `app/data`.
Причина: пользователь попросил, чтобы бот брал не только русские города. Код игры не был привязан к стране — ограничение жило только в данных (сид на 25 городов) и в дефолте загрузчика (RU/BY/KZ/UA), поэтому достаточно было расширить данные и снять фильтр по умолчанию.
Альтернативы: тянуть полный дамп GeoNames (≈200 000+ городов) отклонено — для игры и локального запуска это лишний вес и латиница в названиях ломает буквенную цепочку; автоматически переводить названия из дампа отклонено — машинный перевод ненадёжен для топонимов; ограничиться латиницей отклонено — цепочка строится по русским буквам.
Статус: прогон невозможен (процессы запрещены). Проверено чтением и валидацией JSON: 112 записей, 26 RU + 86 зарубежных, 70 уникальных кодов стран, 71 стартовая буква покрыта (а–я без ё, ъ, ы, ь, ю), BOM отсутствует, хэши `data/seed` и `app/data` совпадают. Осталось прогнать `python -m scripts.seed_cities_seed` и `pytest tests -q` на машине пользователя.

## Update в middleware: «Что-то пошло не так» и мёртвая кнопка GeoGuessr
Решение: добавлены хелперы `app/bot/middlewares/base.py::unwrap_event()` и `event_user()` — на `dp.update.outer_middleware` приходит объект `Update`, поэтому `event.from_user` там всегда `None`. `UserContextMiddleware` теперь достаёт пользователя из вложенного события (`event_user`) и выставляет `data["user"]`/`data["profile"]`/`data["_"]`, но **вниз передаёт исходный `Update`** (подмена сломала бы роутинг aiogram). `ThrottlingMiddleware` разворачивает событие для проверки и ответа (раньше троттлинг не работал вовсе), `I18nMiddleware` использует развёрнутое событие как запасной источник `from_user`. `LoggingMiddleware` больше не падает на `handler.__name__`: aiogram передаёт туда `functools.partial`, поэтому имя берётся через `getattr(handler, "__name__", None) or type(handler).__name__`. В `app/handlers/menu.py` ответы на callback обёрнуты в `_safe_answer()` (Telegram отвечает `Bad Request: query is too old`, если обработка заняла слишком много времени). `ADDED: tests/unit/test_event_unwrap.py` — новый путь: разворачивание `Update` в `Message`/`CallbackQuery`, no-op для обычного события, извлечение `from_user`, `None` для апдейта без события.
Причина: после написания города бот отвечал «⚠️ Что-то пошло не так», а кнопка «🌍 GeoGuessr» не работала. По `logs/errors.log` видно два независимых дефекта: (1) `LoggingMiddleware` падал с `AttributeError: 'functools.partial' object has no attribute '__name__'` уже **после** успешной обработки, поэтому обработчик ошибок отправлял пользователю «⚠️ Что-то пошло не так» на каждый апдейт; (2) `menu_geo() missing 1 required positional argument: 'user'` (и такие же ошибки для `menu_profile`, `menu_settings`, `menu_achievements`) — `UserContextMiddleware` не находил пользователя, потому что получал `Update`, а не `Message`; без инъекции `user` хендлеры меню падали до отправки ответа.
Альтернативы: регистрировать user-context на `dp.message`/`dp.callback_query` вместо `dp.update` отклонено — тогда пришлось бы дублировать регистрацию и терять порядок с DbSessionMiddleware; вытаскивать пользователя прямо в каждом хендлере отклонено — десятки повторений и та же проблема в новых хендлерах; убрать `data["user"]` из контракта отклонено — на него опираются меню, профиль, настройки и GeoGuessr.
Статус: прогон в этой сессии невозможен. Проверено чтением кода, сопоставлением с фактическим traceback из `logs/errors.log` (строки 5908, 6190, 6277, 6349) и статическим чекером импортов (794 импорта, 0 пропусков); тестов 235, включая шесть новых на `unwrap_event`/`event_user`.

## Меню команд одинаково на телефоне и компьютере
Решение: при старте бот регистрирует интерфейс через Bot API — `app/bot/bot_factory.py::setup_bot_ui()` вызывает `set_my_commands(BOT_COMMANDS)`, `set_chat_menu_button(MenuButtonCommands())`, `set_my_short_description()` и `set_my_description()`. Список `BOT_COMMANDS` (10 команд: `start`, `menu`, `play`, `geo`, `profile`, `achievements`, `leaderboard`, `settings`, `help`, `cancel`) — единый для обеих платформ, поэтому меню «/», кнопка меню у поля ввода и приветствие в пустом чате выглядят одинаково. Вызов идёт из обоих входов (`app/main.py` и `run.py`) сразу после `create_bot()`, обёрнут в try/except: если сети нет, бот всё равно запускается. Для команд, у которых раньше был только обработчик кнопки, добавлены `/play` и `/achievements` в `app/handlers/menu.py`, чтобы каждая заявленная команда реально работала. `ADDED: tests/unit/test_bot_commands.py` — новый путь: уникальность и формат имён (Telegram: `[a-z0-9_]{1,32}`), лимиты описаний, наличие хендлера под каждую заявленную команду (сканируется `Command("…")`/`CommandStart()` в `app/handlers`), непустые short/long description.
Причина: на телефоне и компьютере меню выглядело по-разному, потому что приложение никогда не вызывало `set_my_commands`: список команд и кнопка меню формировались клиентом по-своему (на мобильном часто отсутствовал список «/», на десктопе — кнопка меню). Регистрация через Bot API выравнивает отображение без правок клиента.
Альтернативы: настраивать команды вручную в @BotFather отклонено — настройка живёт вне репозитория и расходится с кодом при изменениях; ограничиться reply-клавиатурой отклонено — она не даёт списка «/» и кнопки меню; регистрировать команды только на `ru`-локали отклонено — тогда при другом языке клиента список пропадал.
Статус: прогон в этой сессии невозможен (процессы запрещены: `python`, `pytest`, а также сеть до `api.telegram.org` из песочницы). Проверено чтением и статическим чекером импортов (796 импортов, 0 пропусков), наличие методов `set_my_commands`/`set_chat_menu_button`/`set_my_description`/`set_my_short_description` сверено по исходникам aiogram 3.31.0. Тестов 240.

## Закрытие ресурсов при ошибке запуска (401 Unauthorized)
Решение: в `run.py` появилась функция `shutdown(bot, dp, lock)` — закрывает aiohttp-сессию бота (включая прокси-коннектор `aiohttp_socks`), HTTP-клиент приложения, storage диспетчера и снимает файловый лок; каждый шаг обёрнут в `try/except`, в конце `await asyncio.sleep(0)`, чтобы транспорты успели финализироваться до закрытия event loop. Ей же теперь пользуется `app/main.py`. `setup_bot_ui()` и `ensure_no_polling_conflict()` перенесены **внутрь** `try`, поэтому `finally` выполняется и при 401/сетевой ошибке. `ADDED: tests/unit/test_shutdown.py` — новый путь: закрытие сессии/storage/лока, устойчивость к исключениям внутри `close()`/`release()`, работа без лока.
Причина: при неверном `BOT_TOKEN` запуск падал **до** блока `try/finally`, сессия aiohttp не закрывалась, и на выходе интерпретатор печатал `ERROR asyncio — Unclosed connector` и `RuntimeError: Event loop is closed` из `StreamWriter.__del__` (соединение шло через прокси `aiohttp_socks`). Пользователь видел шум вместо одной понятной ошибки про токен.
Альтернативы: закрывать сессию в `__main__` после `asyncio.run` отклонено — loop уже закрыт, закрытие сессии требует работающего loop; полагаться на `del`/GC отклонено — именно он и выдавал трейсбеки; отключать предупреждения asyncio отклонено — маскировало бы реальные утечки ресурсов.
Статус: прогон в этой сессии невозможен. Проверено чтением, статическим чекером импортов (796 импортов, 0 пропусков) и сверкой, что `dp.storage.close()`/`bot.session.close()` — асинхронные методы aiogram 3.31.0. Тестов 243.
