# Безопасность

Раздел описывает, какие механизмы защиты уже есть в коде, а какие объявлены,
но не подключены. Всё перечисленное проверено чтением файлов; динамических
проверок (сканеров, пентеста) не проводилось.

## Секреты

- Единственное место хранения — `.env` в корне; файл в `.gitignore`
  (строки 9–11), в репозиторий попадает только `.env.example` с заглушками.
- Конфигурация читается один раз через `Settings` (`app/config.py`,
  `env_file=".env"`, `extra="ignore"`); `bot_token` и пароль БД объявлены как
  `SecretStr`, поэтому случайный `repr(settings)` не печатает значение.
- В `docs/` и `README.md` секретов нет — только имена переменных.
- Ключи провайдеров лежат в том же `.env` (`GEONAMES_USERNAME`, `OPENCAGE_API_KEY`,
  `OPENWEATHER_API_KEY` и др.); отсутствие ключа отключает провайдера, а не ломает бота.

Риск: `.dockerignore` пуст, а `Dockerfile` выполняет `COPY . .` — `.env` попадёт
в слой образа. Это нужно закрыть до публикации образа в реестр.

## Доступ администратора

- Список задаётся переменной `ADMIN_IDS` (`list[int]` в `Settings`).
- Проверка — фильтр `IsAdmin` (`app/bot/filters/is_admin.py`):
  `user.id in settings.admin_ids`; применён в `app/handlers/admin.py`.
- Дублирующая функция `is_admin()` есть в `app/utils/security.py`, но нигде не
  импортируется — используется только фильтр.

Отдельных ролей, журнала административных действий и подтверждения опасных
операций (например, `make reset-db`) нет.

## Валидация ввода

- `app/utils/validators.py`: `CITY_RE`, `normalize_city()`, `is_valid_city_name()`,
  `parse_coordinates()` с проверкой диапазонов широты и долготы.
- Правила игры: `last_letter()`/`first_letter()` отбрасывают непроизносимые буквы
  (`ь`, `ъ`, `ы`, `й`), `LETTER_ALIASES` сводит `ё` к `е`, поэтому обойти проверку
  последней буквы сменой регистра или «ё» нельзя.
- `app/utils/security.py` дополнительно содержит `is_safe_text()` (длина ≤ 4096,
  управляющие символы), `escape_user_input()` (HTML-экранирование) и
  `hash_key()` (sha256, 32 символа). Ни одна из этих функций не вызывается из
  кода — фактически защита от HTML-инъекций и слишком длинных сообщений сейчас
  держится на ограничениях Telegram.

## Антифлуд

- `ThrottlingMiddleware` (`app/bot/middlewares/throttling.py`) хранит время
  последнего сообщения в `dict[int, float]` по `tg_user.id` и при интервале меньше
  `THROTTLE_RATE` (0.5 с) отвечает «⏳ Слишком часто».
- Ограничение действует в пределах процесса: при нескольких репликах или
  перезапуске счётчики независимы, память словаря не ограничена по размеру.
- `RateLimiter` (token bucket, `time.monotonic()`) реализован в
  `app/utils/rate_limiter.py`, но не импортируется ни одним модулем — не подключён.

## Внешние вызовы

- Каскад провайдеров: общий дедлайн на вызов, `RETRY_ATTEMPTS = 3` с
  экспоненциальной задержкой и джиттером (0.5–2.0 с).
- Квоты: `QUOTA_LIMITS` в `app/constants.py` — единственный источник лимитов;
  `QuotaManager` пишет расход в Redis, предупреждает при 90 % и бросает
  `QuotaExhaustedError`. Лимит `0` означает «без ограничений».
- Circuit breaker (`app/utils/circuit_breaker.py`): `failure_threshold = 5`,
  `recovery_timeout = 60` с, состояние в Redis по ключам `cb:{provider}:*`;
  при недоступности Redis цепь считается закрытой и запросы не блокируются.
- Ошибки наружу не раскрываются: `AppError.user_message` по умолчанию —
  «Что-то пошло не так. Попробуйте позже.», стек и тексты провайдеров остаются в логах.

## Логи

- loguru, три файла: `logs/bot.log`, `logs/errors.log`, `logs/api.log`; порог —
  `LOG_LEVEL`, каталог `logs/` исключён из git (кроме `.gitkeep`).
- Конвенция «секреты не логируются» зафиксирована в `app/config.py`; массовой
  проверки логов на утечки не делалось, `api.log` может содержать URL запросов —
  ключи провайдеров, если они передаются в query string, туда попадут.
- У `logs/errors.log` намеренно стоит **`diagnose=False`**: loguru с
  `diagnose=True` печатает значения локальных переменных из трейсбека, а среди
  них оказывается объект `Bot` с токеном. Раньше `diagnose=True` был включён —
  исправлено в `app/main.py`. `backtrace=True` оставлен: он показывает строки
  кода, но не значения переменных.

## Режим webhook

При `USE_WEBHOOK=true` приложение поднимает `/webhook` на `0.0.0.0:8080` и
передаёт `WEBHOOK_SECRET` как `secret_token`: Telegram подписывает запросы, и
поддельные апдейты отсекаются. В `docker-compose.yml` порт 8080 не публикуется,
поэтому режим требует reverse-proxy перед контейнером.

## Что нужно доработать

1. Заполнить `.dockerignore` (`.env`, `.venv`, `.git`, `data/`) до сборки образа.
2. Подключить `is_safe_text()`/`escape_user_input()` к обработке пользовательских
   сообщений либо удалить их, чтобы не создавать ложное впечатление защиты.
3. Вынести троттлинг в Redis (`RateLimiter` как заготовка) для нескольких реплик.
4. Заменить пароль `cities/cities` из `docker-compose.yml` на значение из секретов
   и не передавать его через `env_file` в открытом виде.
5. Добавить тесты на антифлуд, права администратора и разбор некорректного ввода.
6. Включить CI (`.github/workflows/ci.yml` пуст): сейчас ни линтер, ни тесты не
   блокируют утечку секретов в репозиторий.
7. Настроить ротацию токена и ключей провайдеров — процедуры нет.
